## 023: Work around ox-blackfriday's details-summary regexp overflow locally (2026-09-13)

**Status:** Final

**Decision:** While `org-blackfriday-special-block` runs, `scripts/export-common.el` answers exactly its details-summary regexp with an equivalent literal search, through scoped `:around` advice on `string-match`. `scripts/check-export-elisp.sh` verifies that the search matches the regexp on small inputs, and that a large details block exports with the override but fails without it. An upstream ox-hugo fix was prepared but not submitted, so the override stays until upstream changes that code.

**Rejected:**
- **Trim or split the SA LP model code block to stay under ~130 KB.** It hides the bug, which returns as the model grows.
- **A character-class regexp (`[^z-a]*`).** It also overflows in Emacs 30 on a 600 KB input.
- **Copy all of `org-blackfriday-special-block` with one line changed.** The copy would drift from upstream. The advice touches only one exact regexp.
- **Submit the upstream PR.** A literal-search helper with ERT tests was ready. Pablo judged the fork, FSF copyright assignment and test-environment overhead not worth it.

**Evidence:** Exporting `situational-awareness-lp.org` failed with "Stack overflow in regexp matcher" inside `org-blackfriday-special-block`. The previous committed version exported fine. With the override, the note exported, and all three published details blocks rendered. The check passes, and Elisp evidence was recorded. ox-blackfriday was byte-compiled, not natively compiled, so the advice applied. If a later build or an upstream change stops the advice from applying, the check's large-block export fails.
**Files:** `scripts/export-common.el`, `scripts/check-export-elisp.sh`, `README.org`.
