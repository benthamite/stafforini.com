## 011: A missing external source is fatal, never a warning (2026-08-08)

**Decision:** Every path this project reads from outside the repo — the five `BIB_FILES`, the Hugo `[[module.mounts]]` sources, the `lib.py` directory constants — must resolve, or the run stops. `generate-work-pages.py` and `process-pdfs.py` raise `SystemExit` on a missing bibliography source instead of warning and continuing, and `tests/test_external_paths.py` (41 tests) resolves the whole set so the failure surfaces in `npm test` rather than in production weeks later.

### The failure this prevents

`scripts/lib.py:BIB_FILES` still named `~/My Drive/repos/babel-refs/` after the 2026-08-03 move retired that directory. `generate-work-pages.py` printed `WARNING: ... not found, skipping` for three of the five sources and carried on: it parsed **16,151** cite keys instead of 25,127, judged **8,891** work pages stale, deleted them, and exited 0. Nothing in the output looked like a failure. Netlify replaces the whole tree on deploy, so shipping that run would have removed 8,891 pages from production.

This is the same shape as decision 009's mount fault, from the same commit (`891b5d3`) and the same move. That is the point: it is a *class*, not two incidents. The generator cannot distinguish "this input was deleted, so prune its outputs" from "this input is unreachable" — so treating the second as the first is destructive by construction, and the only safe reading of a missing source is that the environment is wrong.

Discovered because the redirect audit from decision 010 went from 2 dead rules to 13,104 after the export ran.

**Rejected:**
- **Keep the warning and rely on review.** It had already failed twice — the mounts on 8/8 and the bibs the same week — and both times the warning scrolled past inside a long export log. A warning that precedes deleting 8,891 files is not a warning.
- **Fix the three paths and stop there.** This is what was tried first, and Pablo objected: fixing instance-by-instance had already turned one sweep into three sessions. The subsequent sweep found three more move-broken paths, two of them live — the `gitguardian-triage` skill scanning a directory that no longer existed (so a credential-leak triage would scan zero repositories and report clean) and `80000hours.global/compose.yaml` bind-mounting a path Docker silently creates.
- **Make the mount paths absolute so a repo move cannot break them.** Hugo does allow absolute `source` values for the main project. It narrows the failure mode without closing it — an absolute path still breaks if the *notes* repo moves — and it does nothing for `BIB_FILES`. Detection generalizes; path form does not.
- **Have the generator refuse to prune when its input count drops sharply.** A heuristic threshold would have caught this case, but it guesses at intent, and a legitimate large bibliography removal would then need an override. Asserting the inputs exist is exact.

### Deliberate consequence

These tests touch the real filesystem, so they depend on this machine and on Google Drive being mounted. That is intended: deploys only ever run from here (`netlify.toml`'s build command exits 1 to disable Netlify CI), so an environment that cannot see these paths is an environment that must not deploy.

**Files:** `scripts/lib.py`, `scripts/generate-work-pages.py`, `scripts/process-pdfs.py`, `scripts/rename-cite-keys.py`, `tests/test_external_paths.py`.
