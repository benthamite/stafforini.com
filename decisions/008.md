## 008: Only request Search Console validation for issues whose examples actually resolve (2026-07-28)

**Decision:** In `gsc-indexing-triage`, start a validation only when the issue's representative examples now return what they should on the live site. Validate partial fixes never. In particular, **never request validation for "Page with redirect"** on this property: those 2,462 URLs are legacy WordPress, `/docs/*.pdf`, `/quotes/?p=N`, and `www.` addresses that are *supposed* to 301, so Google recrawls the old URL, still finds a redirect, and fails the validation by design.

On 2026-07-28 this meant validating **Not found (404)** only (224 pending, 0 failed), and skipping Page with redirect, Soft 404, and both duplicate-canonical buckets.

**Rejected:**
- **Validate every issue showing a Failed or Not Started state.** This is not hypothetical — the 2026-05-05 session did exactly this, starting validation on both Page with redirect (1,556 pending) and Not found (375 pending). Page with redirect failed four days later, on 5/9/26, for the reason above, and the failure was still sitting in the report three months later generating alert email. The rejection was never written down, so it was available to be repeated.
- **Validate Soft 404 because its previous validation failed.** The 11 affected pages are thin because the underlying works genuinely carry only a title and a one-line abstract. Nothing about that changed this session, so a validation would fail again and add noise.
- **Validate the duplicate-canonical buckets after fixing part of each.** `/images/*.html` was fixed with `noindex` and 66 work pages got canonicals, but the larger share of "Duplicate without user-selected canonical" is `pdf.stafforini.com/*.pdf`, which stays crawlable on purpose (see `docs/pdf-hosting-policy.md`). Validation is all-or-nothing per issue, so a deliberately partial fix guarantees a failure.
