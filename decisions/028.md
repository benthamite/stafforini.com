## 028: SA LP unknown CUSIPs fail the refresh (2026-11-19)

**Status:** Final

**Decision:** In the SALP note's `sa-data` block, a 13F row whose CUSIP is missing from `CUSIP_TICKER` raises `UnknownCusipError`, which is re-raised past the block's cache fallback. That fails the scheduled refresh (and its macOS failure notification) until the mapping is added. The cache fallback is kept for every other exception, so a transient SEC outage still republishes the last good data.

**Rejected:**
- **Keep the blanket `except Exception` fallback and only add the missing CUSIPs.** That fixes this filing, but the next unmapped security would again publish stale data without any warning.

**Evidence:** The Q3 2026 13F (filed 2026-11-16) added Fermi (314911108 → FRMI) and the Roundhill Memory ETF (77926X320 → DRAM). The parse error was printed to stderr as "using cache", Babel did not surface it, and the daily refresh republished the Q2 2026 portfolio with exit 0 on Nov 16–19. After the change and the two mappings, the refresh picked up Q3. Not yet addressed: a missing information table still `continue`s silently, the VARA data block was not checked for the same pattern, and Babel stderr still does not reach the refresh log.
