## 024: Register the note lastmod stamping hook through package autoloads (2026-09-14)

**Status:** Final

**Decision:** `scripts/inject-lastmod.py` keeps treating a note's `#+lastmod:` keyword as authoritative over git history. The keyword is stamped by a `before-save-hook` in the external `stafforini` package, whose `org-mode-hook` registration is now emitted through `;;;###autoload` cookies on both the hook function and the `add-hook` form, so stamping is active from Emacs startup and the first Org buffer loads the package. For the stale about page, the keyword was set to the file's modification time of the actual edit (`2026-09-13T20:38:20`), not the repair time; the next real save restamps it.

**Rejected:**
- **`(require 'stafforini)` or a `:hook` clause in the Emacs configuration.** Moves package behavior into the config and loads the whole package unconditionally at startup; the cookie keeps the registration with the code it belongs to.
- **Make `inject-lastmod.py` fall back to git when the keyword is older than the last commit.** Hides the broken hook and reintroduces the noisy git dates (bulk mechanical commits) that the keyword exists to avoid.
- **Correct only `about.org`.** Every other note stayed silently frozen; only 16 notes carried a keyword at all, none newer than 2026-08.
- **Restamp by saving now.** Records a time at which no content changed.

**Evidence:** In the live Emacs, `(featurep 'stafforini)` was nil during ordinary editing; the about page's keyword date (2026-05-11) is the day the stamping code landed in the package, so it stamped once while the package happened to be loaded and never again. Batch assertions (registration, in-place keyword rewrite, directory predicate) and a live check in the running session (`:registered t :local-hook t :loaded t`) passed at package commit `496b3d2`. Pending: an interactive save has not yet been observed to restamp a note.
**Files:** `scripts/inject-lastmod.py`; external package `benthamite/stafforini.el` (`stafforini.el`, `README.org`).
