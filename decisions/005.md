## 005: Netlify redirect rules — percent-encoded sources, `_redirects` wins (2026-07-28)

**Decision:** Every rule written into `static/_redirects` must have a **percent-encoded source path**, and any code that generates rules must encode as it writes. `static/_redirects` is processed **before** `netlify.toml`, so a rule in the TOML file only ever sees paths that no `_redirects` rule matched.

Netlify matches rules against the encoded request path. A rule whose source column contains raw UTF-8 never fires, and there is no warning — it looks exactly like a rule that was simply never added. Encode non-ASCII characters and spaces; leave RFC 3986 sub-delimiters (`; , & = + $ ! * ' ( )`) raw, because that is how browsers send them, and encoding `;` breaks rules for multi-author cite keys.

`scripts/rename-cite-keys.py:encode_work_path` is the single implementation. Use it rather than hand-writing `/works/...` rules.

**Why this needed a decision record:** the rule was already discovered once, in `30acdaa` (2026-04-15, *"Netlify \_redirects requires URL-encoded paths to match browser requests"*, 225 `/docs/` rules re-encoded). It was fixed only for `/docs/` and written down only in a commit message. Two weeks later, decision 004 standardised cite keys to ASCII, and the renames it triggered made `rename-cite-keys.py` append seven **unencoded** `/works/` rules for `bródy-`, `comisión-`, `diderot-1755-encyclopédie-`, `gonzálezricoy-`, `jørgensen-`, `müller-`, `organización-`. All seven were dead from the day they were written and stayed dead for three months, showing up in Search Console as "Not found (404)" and costing a full re-investigation on 2026-07-27. The generator, not the file, was the root cause.

**Rejected:**
- **Encode everything with `quote(safe="")`**: turns `;` into `%3B` and breaks the multi-author rules (`/works/daron-acemoglu;giuseppe-de-feo;.../`) that Netlify matches raw today.
- **Write both a raw and an encoded rule for each slug**: doubles an already 42k-line file to defend against a case that cannot occur — Netlify normalises the incoming path, so the raw spelling never matches. Verified live: both spellings 404'd before the fix, both 200 after.
- **Put structural rules in `netlify.toml` because it is easier to read**: only safe for paths `_redirects` does not already claim. Four tango feed rules added there on 2026-07-28 were shadowed by two pre-existing `_redirects` rules and silently did nothing.

**Check before adding a rule to `netlify.toml`:** grep `static/_redirects` for a rule that would match the same path first. A shadowed rule fails silently.

**Files:** `scripts/rename-cite-keys.py` (`encode_work_path`, `rename_redirects`), `tests/test_rename_cite_keys.py`, `static/_redirects`, `netlify.toml`.
