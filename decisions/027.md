## 027: Fast quote deploys (2026-09-18)

**Status:** Final

**Decision:** `deploy.sh --fast-quote=WORK-SLUG` deploys an already-exported diary quote that was added or edited by rendering, into the preserved `public/` snapshot, the static `fast_quote` segment in `hugo.deploy.toml` (home, sitemap, taxonomy/term pages, `/quotes` and `/quotes/**`) plus a per-run `fast_quote_works` segment naming the affected work pages. The per-run segment lives in a throwaway config layer passed as a third `--config` file, because segments are static configuration and a quote appears on exactly one work page out of ~25k. Slugs are checked against `content/works/` before they are interpolated into TOML. The search index is left stale, as with `--fast-note`. Two probes promote the run to a complete quick build: the existing PDF-links check, and a new `verify-site.py --profile quote-pages` that fails when a rendered quote page has no markdown source, since a render that never cleans cannot remove a deleted or renamed quote. `stafforini-publish-quote` chains this after the export, passing the quote's `work` front-matter value.

**Rejected:**
- **Render `/works/**` in the static segment.** Works are ~25.5k of ~29.5k pages, so this is nearly a full build and would erase the saving.
- **Detect changed quotes from mtimes.** Every quote export rewrites all ~2,300 quote files, so mtimes mark everything as changed. The caller already knows the work, so it passes it.
- **Rebuild Pagefind over the preserved tree.** It would be correct, since `public/` is a complete snapshot, but it took 71s of the saving on 2026-09-18. A quote missing from search until the next full deploy is acceptable.
- **Extend `fast_note` to cover quotes.** It would make every note deploy render ~3,900 extra pages, and it would still not know which work page to render.

**Evidence:** Timings from the 2026-09-18 06:31 `export-quotes.sh && deploy.sh --quick` run: build 87s, Pagefind 71s, verify 59s, Netlify 132s. A stubbed-upload `--fast-quote=pessoa-1982-livro-do-desassossego` run took 54s end to end: segment render 10s (3,907 pages), fast verification 1s. It re-rendered only that work page among works, and the deploy tree remained complete at 58,505 files. A planted orphan page under `public/quotes/` triggered the fallback to a full quick build, and that build removed it. The Netlify upload time for a fast-quote deploy has not been measured with a real upload.

**Files:** `scripts/deploy.sh`, `hugo.deploy.toml`, `scripts/verify-site.py`, `tests/test_verify_site.py`, `PUBLISHING.md`, `CLAUDE.md`; `stafforini.el` (`stafforini-publish-quote`).
