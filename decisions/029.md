## 029: One daily SALP/VARA refresh job, one deploy (2026-11-22)

**Status:** Final

**Decision:** launchd runs `scripts/model-refresh.sh` (job `com.stafforini.model-refresh`, daily 03:37). It runs `sa-lp-refresh.sh --no-deploy`, then `vara-refresh.sh --no-deploy` (VARA runs even if SALP failed), then deploys once with `--fast-note` if at least one refresh ran to the end. A refresh signals that it ran to the end (rather than skipping on an Emacs lock) by touching `$REFRESH_COMPLETED_FILE`. The heartbeat `com.stafforini.model-refresh.success` is written only when both ran to the end and the deploy completed. Run directly, either script still deploys by itself, for manual refreshes such as `--with-sensitivity` after a filing. The two old jobs and their per-job heartbeats were retired.

**Rejected:**
- **Keep both jobs and let only the later VARA job deploy.** It couples the jobs implicitly: when VARA fails or skips, the SALP changes would stay undeployed with no failure signal.
- **Keep two deploys a day.** Each Netlify production deploy costs 15 credits; the second daily deploy cost about 450 credits a month (15% of the 3,000-credit Pro plan).

**Evidence:** On 2026-11-21 Netlify warned that 75% of the month's credits were used. Of the 72 production deploys in the cycle from 23 Oct, 34 came from the 06:40 and ~07:15 UTC refresh deploys. `tests/test_refresh_heartbeat.py` covers the wrapper's outcomes with stub scripts. Pending: the first real run on 2026-11-23 at 03:37.
