# 016: Cross-note comparisons run the sibling note's own code (2026-08-22)

**Decision:** The VARA note's SALP-comparison block computes the SALP series by
extracting the `sa-data` and `sa-lib` blocks from the SALP note's org source and
executing them unchanged in an isolated namespace, mirroring the exact calls of
that note's chart block. The correctness gate is reproducing the SALP note's
published figures to the decimal (verified: eq Sharpe 1.13, opt 1.28, scaled
+132.62%, DD −45.8%). An incompatible change to the SALP note (e.g. a block
rename) fails the VARA refresh loudly; there is no fallback.

**Rejected:**
- **Reimplement a simplified 13F-only SALP model in the VARA note:** shipped
  once; it omitted the SALP note's 13G-layered rebalance timeline and produced
  an equity-proxy Sharpe of 1.05 against the SALP note's published 1.13,
  understating the comparator and flattering VARA. The divergence was mistaken
  for an inconsistency by the reader (the user). Explicitly rejected as a
  shortcut.
- **Duplicate `SA_13G_DISCLOSURES` and the SALP CUSIP map into the VARA note:**
  a second hand-maintained copy silently goes stale the next time SALP files a
  13G and only the SALP note is updated; it also cannot reproduce the option
  machinery's per-position `selected_on` handling for layered periods.

**Files:** `notes/public/value-aligned-research-advisors.org` (`vara-chart-salp`).
