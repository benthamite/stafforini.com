## 009: Note attachments reach production through Hugo mounts, not through `static/` (2026-08-08)

**Decision:** Binary attachments that belong to a note — the archived Anki decks, the Randy Pausch summary — live beside their org source in `~/My Drive/notes/public/<dir>/` and reach the build through `[[module.mounts]]` entries in `hugo.deploy.toml` and `hugo.dev.toml`. They are not copied into this repo. If those files ever appear to be missing from production, **fix the mount, do not re-import the files.**

### Why this needs a record

The mount is silently fragile in a specific way: a `[[module.mounts]]` source that does not exist is **not** a Hugo error. The build succeeds and simply omits the files, so nothing surfaces until something downstream links to the missing content.

That is exactly what happened. The 2026-08-03 repository move from `~/My Drive/repos/stafforini.com` to `~/repos/stafforini.com` invalidated both mount sources, which were written as `../../notes/public/<dir>` and had resolved into Drive only by virtue of where the repo used to sit. Commit `891b5d3` ("Point paths at the post-migration repository locations") missed them. Two directories vanished from every build: 36 archived Anki decks and a 43 MB attachment.

**The stakes are higher than a broken link.** Netlify replaces the whole tree on each deploy, so the first successful deploy after 8/3 would have deleted all 50 MB from production. The note itself records that these decks are the only surviving copies on the open web — AnkiWeb deletes shared decks with low download activity, and Pablo re-uploaded what he could regenerate from his master deck.

**Correction (2026-08-08, second session):** an earlier version of this record, and the session log of the same day, described the decks as existing "nowhere else except production." That is wrong. All 36 `.apkg` files and the Pausch attachment are tracked in `~/My Drive/notes` and pushed to `benthamite/notes`; the commit containing them is on `notes/master`. They are irreplaceable in the sense that AnkiWeb no longer has them, but they are not un-backed-up, and a bad deploy is recoverable from git. The real exposure is silent omission from the build, not data loss.

**Where they live, decided 2026-08-08:** the decks stay in the notes repo. Moving them into `static/` (90 MB into this repo and its history, breaking the attachments-beside-their-source convention) or onto R2 (link rewriting plus a sync step) were both considered and rejected: neither addresses the actual failure mode, which is a mount that resolves to nothing. Detection does. `tests/test_external_paths.py` now asserts every `[[module.mounts]]` source resolves, so a broken mount fails the suite instead of quietly shrinking the deploy. See decision 011.

Fixed in `0cfde38` and `ee0fc4d` by pointing both mounts at `../../My Drive/notes/public/<dir>`.

**Rejected:**
- **Download the files from production into `static/` and gitignore them.** Tried first, in `13ed4a8`, and it changed nothing: the deploy config's `[module]` block replaces the default static mount with an explicit list, and `static/anki-decks-from-the-lesswrong-community` is not on it. The next deploy still failed verification on the same 37 broken links. Reverted in `000ad9e`. The general lesson: when production serves a file the repository does not appear to have, confirm how the build is *supposed* to obtain it before concluding the two genuinely disagree.
- **Commit the 50 MB of decks to git.** Would have worked, but it permanently bloats history for files that are not source, and it is not reversible without a history rewrite. Only worth revisiting as part of the open question below.
- **Strip the "archived" links from the org note.** Superficially makes verification pass. It would have destroyed 36 working downloads to silence a warning about them, which is backwards.

### Open

Where these files should live *durably* is still undecided. They currently exist in exactly two places — the notes repo and production — and are reached by a path that a directory move has already broken once. A test asserting that every `[[module.mounts]]` source resolves would make the present arrangement safe enough to keep; moving them into `static/` or pushing them to R2 alongside the PDFs are the alternatives.

**Files:** `hugo.deploy.toml`, `hugo.dev.toml`, `~/My Drive/notes/public/anki-decks-from-the-lesswrong-community/`, `~/My Drive/notes/public/summary-of-time-management-by-randy-pausch/`.
