## 022: Work-page PDF links follow current bibliography attachments (2026-09-13)

**Status:** Final

**Decision:** Generate `data/pdf-links.json` from the current bibliography's eligible attachments, using the same selection rules as PDF processing. A link requires a processed manifest entry whose source path matches the current attachment, plus the generated PDF and thumbnail. The original attachment itself may be offline. Removing an attachment removes its link; changing its path hides the previous PDF until the replacement is processed. Inherited attachments remain subject to the existing crossref and hosting rules.

Refresh this inventory during data regeneration, supported builds and deployments, including quick and fast-note deployments. If fast-note's retained work pages disagree with the refreshed inventory, promote to a full render. Missing required sources or inventories abort, consistently with decision 011. Retained PDF files and thumbnails do not establish current attachment membership; removing a website link does not require deleting files from R2.

**Rejected:**
- **Use thumbnail existence as link eligibility.** The Hugo 0.165 symlink regression was initially repaired by switching from `fileExists` to an asset lookup. That restored links but also exposed a stale Sinhababu PDF after its bibliography attachment had been removed. Neither lookup can establish current bibliography membership.
- **Remove only the stale generated asset.** This would treat one symptom while leaving future attachment removals and replacements unreflected in work pages.

**Evidence:** Commit `5df239e` implements the shared inventory and rendered transition tests. The session reported 478 full-suite passes, followed by 35 targeted passes and three render-test passes after final changes; these are separate verification scopes. On 2026-09-13, the session verified the deployed Sinhababu work page had no PDF link while the Parfit page retained its correct link (Netlify deploy `6aa673839e2cb9dfd2a0a985`). The recording pass inspected the implementation and tests; it did not repeat the live checks.
