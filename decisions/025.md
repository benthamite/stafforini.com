## 025: No shell-loop traversals of the notes tree from an agent session (2026-09-14)

**Status:** Final

**Decision:** Agents working on this site must not run scripted bulk traversals over `~/My Drive/notes` or other large Drive trees from a shell parented by Emacs: no recursive `grep` with `**` globs, no `for f in $(git ls-files ...)` loops that open each file, no `find | xargs -P ... sh -c` fan-out. Use the repository's entry points (`scripts/export-notes.sh`, `scripts/inject-lastmod.py`, the dotfiles `batch-test.sh`), a single known file, or `git ls-files` for names only. Quiet noisy batch output at its source rather than by piping.

**Rejected:**
- **A malicious or quarantined file inside the notes tree.** The block record is `url-<sha256>` with no matching URL in the quarantine database, and no file was ever identified; three traversals of differing shape all hit the same identifier.
- **Google Drive placeholder materialization as the trigger.** Unproved; the repository's own Python/Emacs batch runs traverse the same 10,217 files under `xprotectd` observation without a deny.
- **A native-compilation `.eln` false positive.** Those log lines were routine Gatekeeper scan results during an Emacs start.
- **Bisecting subtrees, unredacting private log data with a configuration profile, or overriding the block in Finder.** One killed session per bisection step; the profile is invasive and prospective only; an override would suppress the signal.

**Evidence:** `syspolicyd` displayed an XProtect blocked prompt at 2026-09-13 20:43:29 and 20:53:01 and 2026-09-14 08:24:26, each within seconds of such a loop; at the latter two, `xprotectd` logged "Killing container due to rules engine deny" and "Prompting user about blocked scripted malware execution". The agent shell's ancestry was `zsh <- claude <- Emacs`, and Emacs died each time. Apple documents macOS 26.4 terminal and script protections that trace the process tree of terminal commands. Which rule matched is inferred, and the `url-` identifier remains undecoded. An independent Codex review reached the same process-tree reading.
**Files:** `scripts/lib.py` (`is_dataless`), `scripts/export-common.el` (silent org-id scan).
