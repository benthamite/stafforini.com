# 017: Unfillable option rows auto-exclude with printed reasons (2026-08-22)

**Decision:** In both 13F notes, `download_option_prices` records a documented
exclusion for *any* period when the chain fetch succeeds but no listed contract
falls inside the expiry window (or no quotes return for the selected contract),
instead of raising for non-final periods. Every omission prints under the
results table with its reason. A failed API call still raises; only a
successful-but-empty selection excludes.

**Rejected:**
- **Raise for intermediate periods (original design):** produced serial
  fail→fix→rerun cycles (one ticker per retry loop) and made sensitivity sweeps
  impossible, since alternate expiry windows fail on different names — the
  reason the SALP note's sensitivity section had been commented out as broken.
- **Hand-maintained `OPTION_PRICE_EXCLUSIONS` pre-population:** equivalent
  outcome with manual toil (22 entries for VARA alone) and per-sweep-combo
  variants that cannot be enumerated by hand.

Evidence: 22 of 292 VARA (position, period) selections had no contract in the
9–15-month window (typically names whose only long-dated listings are January
LEAPs); all were under 1% of the quarter's reported value (largest: EWT put,
0.76% of Q2 2025).

**Files:** both notes' lib blocks
(`situational-awareness-lp.org`, `value-aligned-research-advisors.org`).
