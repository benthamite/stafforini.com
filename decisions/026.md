## 026: Freshness checker reads the note's warrant adjustment (2026-09-17)

**Status:** Final

**Decision:** The filing skill's `check_freshness.py` derives its calculator expectations from the note instead of assuming as-filed values. It parses the `SA_13F_WARRANT_ADJUSTMENTS` literal out of `situational-awareness-lp.org` without executing it, mirrors the producer's scaling for the adjusted rows, expects the `; TICKER adds N pre-funded warrants from the ...` label suffix those rows generate, and accepts a cent-rounded reported value for exactly those ticker/type keys. Every other holding still has to be an integer dollar amount and the plain label still has to match exactly. The guarantee is deliberately bounded: the checker proves the published artifacts agree with the note's declared adjustment, never that the warrant count itself matches the underlying Form 3/4. Both the `.claude` and `.codex` copies carry the change, and the printed LIMIT line names the new gap.

**Rejected:**
- **Relax the assertions.** Accepting any label and dropping the integer requirement would clear the failure, but the two checks exist to catch a stale calculator, which is the failure mode the filing gate is for.
- **Leave the checker failing and read around it.** It was the only failing check against artifacts that were in fact correct, so every future filing refresh would have had to decide again whether the FAIL was real. A gate that reports a known-false failure stops being read.

**Evidence:** Observed on 2026-09-17: the checker reported `FAIL: calculator current label and all three modes' aggregate holdings` against artifacts the 12:10 scheduled refresh had just published. The checker was committed on 2026-09-06 (`4f8b2b9`); decision 021's warrant treatment landed on 2026-09-12 (`272ab8461`, `e68fc14`) and changed both the calculator label and the SHAZ reported value, which `build_mode_data` rounds to the cent. After the change the checker returns 7/7 PASS on unmodified artifacts. Nine regression tests were added; `npm test` reports 486 passed. Still unproven: nothing runs the checker against the real note in CI, so the same drift can recur — the fixture-only suite is what let it go unnoticed for six days.
