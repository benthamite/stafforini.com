## 030: Cut Netlify bandwidth with font subsets and capped feeds (2026-11-22)

**Status:** Final

**Decision:** `scripts/subset-fonts.sh` splits each Source Serif 4 variable font (sources in `fonts-src/`, not deployed) into a Latin file (Google Fonts' "latin" range) and a "rest" file with every other character the font covers. It generates `assets/css/_fonts.css`, where each face's `unicode-range` is exactly its file's coverage, so a page downloads the rest file only when it uses one of those characters. Files carry a `-vN` suffix because `/fonts/*` is served immutable for a year. Every RSS feed is capped at its 50 most recent items (`[services.rss] limit` in `hugo.toml`; the templates already honoured it).

**Rejected:**
- **Put Latin Extended in the first file too.** That subset came to 244 KB against 196 KB; Latin Extended characters appear on only a few percent of pages.
- **Drop the non-Latin glyphs.** Smaller, but Cyrillic, Turkish, Greek and maths text would fall back to another font.
- **Shorten long notes in the notes feed.** The notes feed (30 items, 274 KB compressed) is dominated by the Emacs config and SALP notes, but SPEC.md asks for full content. Deferred to Pablo.

**Evidence:** Netlify Observability, 15–22 Nov: 11.6 GB, of which the fonts were 4.6 GB, the feeds 2.9 GB (`/index.xml` was 6.2 MB compressed per fetch) and `/works/` 0.76 GB. After the 2026-11-22 deploy, the live sizes are: `/index.xml` 283 KB, quotes feed 20 KB, Roman Latin font 196 KB (from 430 KB). Checked in Chrome on a local production build: a plain note loaded only the two Latin files; `/works/` also loaded the rest files and rendered Cyrillic and Turkish in Source Serif. The bandwidth saving itself is still unmeasured.

**Files:** `scripts/subset-fonts.sh`, `fonts-src/`, `static/fonts/`, `assets/css/_fonts.css`, `assets/css/_base.css`, `layouts/partials/head.html`, `hugo.toml`.
