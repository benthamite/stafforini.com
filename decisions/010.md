## 010: The redirect-target audit stays a standalone script for now (2026-08-08)

**Decision:** `scripts/audit-redirect-targets.py` resolves every literal local `_redirects` target against a rendered tree and reports the ones that land on nothing. It is deliberately **not** wired into `scripts/verify-site.py`, which is the deploy gate. Wire it in once the two known dead rules are resolved — not before.

### Why it is not in the gate yet

The audit currently reports exactly two rules, both from the 2026-04-15 bulk WordPress import (`e8b6b0c`):

```
line  303: /quotes/  p=321   -> /quotes/kennedy-economics/
line 1598: /quotes/  p=3919  -> /quotes/kennedy-bernhard-von-bulow/
```

Neither quote was ever migrated into `~/My Drive/bibliographic-notes`, so both rules 301 into a 404. What to do about them is a content decision Pablo has explicitly deferred: both are Robert Kennedy quotes recoverable from the Wayback Machine (`?p=3919` captured 2025-05-20, `?p=321` captured 2026-03-05), and the citing work `Kennedy1969ThirteenDaysMemoir.org` is already in the bibliography. So the choice is real — recover them, or drop the rules.

Wiring the audit into `verify-site.py` today would fail verification on those two rules and block **every** deploy, including unrelated note publishing, until that decision lands. That is disproportionate to the harm, which is two legacy query URLs redirecting to a 404 instead of 404-ing directly.

The audit found these two among 42,133 rules (2,407 of them `/quotes/` rules) with no false positives. Coverage is 9 unit tests in `tests/test_audit_redirect_targets.py`.

**Rejected:**
- **Wire it in immediately and let the deploy break.** Honest, and it would force the decision, but it imposes an unrelated-deploy outage on Pablo for a cosmetic defect. The forcing function is not worth the collateral.
- **Wire it in with an allowlist exempting the two known rules.** This is precisely the "silent fallback or workaround" that the standing operating rules prohibit unless labelled, justified, and approved. An exemption list also rots: the next dead rule gets added to it rather than fixed.
- **Check targets against `content/` instead of a rendered tree, so it can run in `npm test`.** Cheaper and needs no build, but `content/` is generated and gitignored, and targets include static files and section pages that have no `content/` equivalent. Resolving against the rendered tree is the only check that matches what Netlify will actually serve.

### Why this class of fault needs a check at all

A rule whose target was later renamed or deleted keeps returning its 301, so nothing about the redirects file looks wrong. The fault surfaces weeks later as a Search Console "Not found (404)" entry for the **target**, which reads as an unrelated missing page. The 2026-07-28 session fixed five such rules by hand for `/works/` targets and did not think to check `/quotes/` targets; those two survived another six weeks and generated the 8/7 validation-failure alert.

**Files:** `scripts/audit-redirect-targets.py`, `tests/test_audit_redirect_targets.py`, `scripts/verify-site.py` (the eventual home), `static/_redirects`.
