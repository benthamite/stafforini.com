** gsc-indexing-triage
:PROPERTIES:
:ID:       C3D0D6E2-436C-45FB-9388-70920301D517
:END:

The project-local =gsc-indexing-triage= skill handles Google Search Console
Page indexing alerts for =stafforini.com=. Read-only triage includes opening
Search Console in a browser to inspect failed examples and checking the
affected URLs locally or live. It does not write a log, export content or apply
fixes unless the request authorizes those changes. The link helper reports
extraction failures explicitly, validates link destinations and never logs in.

Deployment, clicking Search Console validation buttons, and archiving Gmail
messages remain externally visible actions and require explicit authorization
in the current invocation. That gate governs what the skill may do; it is not
a licence to do less. Within whatever scope an invocation allows, the skill is
expected to finish the work in one turn rather than return a to-do list, and to
stop only for judgments the repository cannot supply — which of two defensible
outcomes is wanted, or anything touching the shared =babel-refs= bibliography,
published content, or another property.

Paths, item keys, and command recipes live in the skill's
=references/stafforini-com.md=, mirrored under both =.claude/skills/= and
=.codex/skills/=. Those paths are absolute, so they have to be updated
whenever the repository moves; they now point at =~/repos/stafforini.com=.

Decision 008 says not to validate this property's =Not found (404)= or =Page
with redirect= buckets because they contain intentional backlogs. This is a
site policy, not a claim that Google can never validate either category.
Inspect relevant examples in both buckets for genuine regressions, including
broken redirect targets; recent crawl dates prioritize work but do not exclude
older important URLs. Use bounded live checks and distinguish local fixes,
deployed behavior and Google's recorded state. The skill's reference carries
the policy, evidence limits and source links.

** update-situational-awareness-filing

The paired project-local filing skill distinguishes read-only research from
local recomputation and explicitly authorized publication. Its checker tests
current full-13F artifact consistency, not SEC completeness, financial-model
correctness, a newly completed sensitivity run or live publication. The skill's
=references/filing-refresh.md= describes current producer limitations and the
affected SALP/VARA artifacts.

=DRY_RUN=1 scripts/sa-lp-refresh.sh --with-sensitivity= still reads credentials,
uses data services and changes local results, caches and exports; only automatic
commit/push/deploy are suppressed. A filing refresh must verify all three proxy
modes and both generated standalone scripts. Filing-related date/link/citation
changes do not qualify for the limited =--fast-note= deployment path.

** SA LP Refresh
:PROPERTIES:
:ID:       8431CA99-D3B5-4497-8E2F-BDECC669517C
:END:

=scripts/sa-lp-refresh.sh= evaluates every dynamic Babel block used by the
Situational Awareness LP note, including the AIS comparison block, before
exporting and committing the generated static chart/calculator assets.
Both it and =scripts/vara-refresh.sh= drive a =emacs -Q --batch= process
through =scripts/sa-lp-init.el=, which sets =debug-on-event= to nil so a
SIGUSR2 aimed at the interactive Emacs (the =emacsk= shell helper) cannot
arm the debugger and abort the batch run with exit 255.
