** gsc-indexing-triage
:PROPERTIES:
:ID:       C3D0D6E2-436C-45FB-9388-70920301D517
:END:

The project-local =gsc-indexing-triage= skill handles Google Search Console
Page indexing alerts for =stafforini.com=. Read-only triage includes opening
Search Console in a browser to inspect failed examples and checking the
affected URLs locally or live.

Deployment, clicking Search Console validation buttons, and archiving Gmail
messages remain externally visible actions and require explicit authorization
in the current invocation.

Paths, item keys, and command recipes live in the skill's
=references/stafforini-com.md=, mirrored under both =.claude/skills/= and
=.codex/skills/=. Those paths are absolute, so they have to be updated
whenever the repository moves; they now point at =~/repos/stafforini.com=.

Two issues must never be validated: =Not found (404)= and =Page with
redirect=. Google fails a validation if any affected URL still shows the
issue, and for both of these the affected set permanently contains URLs that
are meant to show it — correctly retired pre-WordPress pages in the first,
intentional legacy 301s in the second. Validating them only produces another
"Some fixes failed" email. =Not found (404)= is still worth reading for
genuine lost redirects; =Page with redirect= can be ignored. The reference
file carries the full rule.

The note exporter resolves =id:= links through the generated ID maps.
Links to unpublished targets become plain text, links to published
notes become =/notes/slug/= URLs, and links to headings inside the
same note become local fragment links such as =#copycat-delays=.
